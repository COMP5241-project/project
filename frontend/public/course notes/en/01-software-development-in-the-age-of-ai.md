# Software Development in the Age of AI

> Distilled from the course deck (83 slides). A survey of how AI is reshaping software development: vibe coding, agentic coding, productivity evidence, risks, and what skills matter now.

---

## 1. The rise of AI-assisted coding

- Stack Overflow Developer Survey 2025 frames the current AI-in-development landscape.
- NVIDIA's Jensen Huang: AI will let everyone become a "programmer" through natural-language interaction.
- Real cases: a non-coder built a full-stack app (frontend + backend + database) in 12 days; Microsoft's CEO says AI writes up to 30% of their code; Anthropic's CEO predicted all code would be AI-generated within a year.
- **Where AI is used across the SDLC:**
  - **Discover** — quickly understand and navigate unfamiliar codebases.
  - **Design** — thought partner for planning/architecture; multiple implementation options, refactoring strategies, bug-fix plans; write specs.
  - **Build** — implement code, write/run unit tests, draft commits and PR messages.
  - **Deploy** — automate CI/CD, configure environments, manage deployments.
  - **Support & scale** — diagnose errors, analyze logs, suggest fixes; large-scale refactoring.
- **Tool landscape:** consumer (Replit, v0, Lovable, bolt…) and developer (GitHub Copilot, Cursor, Windsurf, Claude Code, Antigravity, Trae, Opencode), plus design tools (Figma, Google Stitch).

## 2. Vibe coding

- Coined by **Andrej Karpathy**: "fully give in to the vibes… forget that the code even exists." Errors are fixed by copy-pasting the message back in.
- The practitioner steers by **outcome**, not by reviewing every line.
- It has moved into the enterprise: e.g., a non-engineer sales/ops director at iCHEF (restaurant tech, TW) built multiple internal AI mini-tools with Gemini.
- Agentic coding makes prototype generation a matter of minutes/hours instead of weeks.

## 3. From LLM to autonomous agents

Three levels of autonomy:

| Level | Description |
|---|---|
| 1. Reactive | Purely responsive; needs step-by-step human instructions; cannot complete tasks on its behalf |
| 2. Collaborative | Works alongside a human; handles complex prompts, drafts, automates parts of a workflow, but relies on human direction, feedback, approval |
| 3. Autonomous | Given a high-level goal, the agent plans steps, uses tools, and completes the task end-to-end |

**Autonomy ladder (autocomplete → autonomy):**

1. Autocomplete — token prediction in the editor
2. Inline suggestions — whole functions from a signature
3. Chat generation — describe a feature, receive working code
4. Coding agents — multi-file edits, tool use, tests, self-correction loops
5. Autonomous agents — clone repos, plan in a sandbox, run tests, submit PRs

## 4. How coding agents work

- Operate in three phases: **gather context → take action → verify results**.
- Tool families: file operations (read/edit/create/rename), search (glob, regex, explore), execution (shell, servers, tests, git), web (search, docs, error lookup).
- Example: "fix the failing tests" → run test suite → read errors → search relevant files → read them → edit → re-run tests to verify.
- **Context window**: holds the session's instructions, files read, responses. **Subagents** run in separate context windows so large reads stay out of the main one; only summaries return.

## 5. Harness engineering

- OpenAI case study: **3 engineers, 5 months, ~1M lines of code, 0 lines written by hand** — all application logic, tests, CI config, docs, tooling generated by Codex. "Humans steer. Agents execute."
- "The team's primary job is no longer to write code, but to design the environment, specify intent, and build feedback loops that let agents do reliable work."

| Concept | Governs |
|---|---|
| **Prompt engineering** | What you say: wording, structure, system/user prompts, few-shot examples |
| **Context engineering** | What the model sees: codebase, architecture, conventions, intent |
| **Harness engineering** | How the whole agent system operates: tools, guardrails, feedback loops, observability, versioning, error recovery |

> **Agent = Model + Harness.**

## 6. Known failure modes of AI-generated code

- **The purple button problem**: `bg-indigo-500` appears so often in tutorials/open source that AI statistically associates "button" with that purple shade — AI UIs default to purple.
- **Security incidents from vibe-coded apps:**
  - An AI-built SaaS with "zero hand-written code" suffered bypassed subscriptions, exhausted API keys, database corruption.
  - Tea (women-only dating app): Firebase left open with no auth → **72,000+ private images and 13,000+ government IDs leaked**; critics blamed unreviewed AI-generated code.
- Typical AI security holes: no rate limiting on login, unsecured API keys, admin functions guarded only by frontend routes, DB manipulation from the frontend.
- **The 70% problem / last-mile gap**: the first 70% (patterned, framework-standard code) is fast; the final 30% — edge cases, architecture, maintainability — hits diminishing returns and needs human expertise.
- AI boosts **output** but also **rework**; GitClear found 5+ line duplicated blocks ~8× more frequent in 2024 vs 2022. AI suggestions skew toward *adding* code rather than moving/updating/deleting.

## 7. Productivity evidence

- **Hardest part of software engineering is understanding what needs to be built** — "80% of my job is filling the enormous gaps between the specs and reality."
- **Stanford study (~100k developers, 27 companies, 136 teams):**
  - **Greenfield** (new codebases, low complexity): **+30–40%** productivity.
  - **Brownfield** (large, mature codebases): only **0–10%** gain.
  - Effectiveness drops sharply as codebase size grows: context-window limits, signal-to-noise, domain logic; even SOTA models lose accuracy with long contexts (e.g., 90% → 50% at 32k tokens).
- **Brownfield is "remodeling a kitchen while people are still living in the house."**
- Real-world coding is messy: vague business requirements, legacy systems, hidden state (caches, queues, scattered config), cross-team knowledge — far beyond algorithm puzzles (GPT-5 solved all 12 ICPC finals problems, yet struggles with production reality).

## 8. Labor and career impact

- Anthropic warns AI could eliminate up to **50% of white-collar entry-level jobs in 1–5 years**; Salesforce announced it would stop hiring new software engineers (2025).
- **Junior developer crisis**: the tasks AI handles best (boilerplate, simple bugs, test generation) are exactly the training ground for juniors. Removing the struggle removes first-principles learning — eventually nobody understands the systems deeply enough to debug them when AI fails.
- Intern example: before AI, delegating a task required specs, handoff, check-ins, reviews; with AI, once requirements are thought through, the manager can hand them straight to AI. **Valuable skill shifts from executing well-specified tasks to defining, scoping, and reasoning about problems.**
- Coding becomes a **foundational skill**: not knowing how to code won't work, but *only* knowing how to code won't be enough.

### New roles & building blocks

- **AI Engineer** (builds apps on AI models via APIs) vs **ML Engineer** (builds the models/APIs). Needs: strong SE fundamentals, reliable/scalable apps, modern AI tooling, UX focus.
- GenAI building blocks beyond calling an LLM API: prompting techniques, agentic frameworks, **evals, guardrails, RAG, embeddings/vector DBs, fine-tuning, MCP, reasoning models, async programming, data extraction**.
- **2023 vs 2026 job market**: 2023 = learn HTML/CSS → demo projects → apply. 2026 = system design + cloud + DevOps + networking + performance + communication + LLM APIs + AI agents + prompt/context engineering + real shipped projects.
- **Zara Zhang** (humanities background, non-technical builder): 30k+ GitHub stars using Claude Code & coding agents; argues coding is shifting from a *profession* to a *general skill* like writing — humanists are needed to notice real user needs and judge "good vs better."

## 9. The new human value: from doing to defining

- **HBR**: "AI makes building easy. Choosing what to build is harder." AI is good at execution, not ideas. Humans own the **what and why**; define the problem roughly, prototype, then sharpen the problem. Evaluate prototypes by the questions they surface, not how finished they look.
- **Product mindset**: think in user and business outcomes over the product's whole life. Ask "what problem are we solving?" and "is this the best solution?" before implementing; understand how the product makes money; challenge unclear requirements.
- **FireCut case** (AI video-editing plugin for Premiere Pro / DaVinci Resolve):
  - Collected 50+ real problems; filtered ideas with 4 questions: *painful enough? can users pay? can I reach them? is the market growing?*
  - **Unfair advantage**: access to a YouTuber's editing team → real beta users; observed editors' actual workflow → built a *plugin*, not a web app. "Don't design from assumptions; observe how people already work."
  - Smallest possible prototype (one feature: auto-remove pauses) built in ~2 days with GPT-4; ~200 signups, ~20 beta testers; iterated daily for 6 weeks; hired engineers only after ~$30k monthly revenue.
- **Attention is the scarce resource**: AI doesn't create more human attention or trust; as more people ship, competition and the need to stand out rise.
- **Restaurant menu analogy**: a menu can look great and still be the wrong menu — "there is no test for that." AI lowers the cost of execution; direction and judgment come from a person.
- **Taste**: "An agent can tell you if a thing looks correct against a spec — not that it's *good*." Engineers remain answerable for systems; accountability grows from expertise and trust.

### New bottleneck: review capacity

- Code generation is easy; **verification is the differentiator**: writing good tests (unit/integration/e2e), reading code critically, debugging systematically.
- **Rise of the architect**: judged by clarity of specifications and rigor of verification, not lines of code.

### Vibe coding → structured AI-assisted coding → agentic engineering

| Dimension | Vibe coding | Structured AI-assisted | Agentic engineering |
|---|---|---|---|
| Intent | Casual prompts | Detailed prompts with examples/constraints | Formal specs, architecture docs, memory files |
| Verification | "Does it seem to work?" | Manual testing, spot-checks | Automated suites, CI/CD gates, LLM judges |
| Codebase understanding | Minimal | Selective review of critical paths | Comprehensive architecture review |
| Error handling | Paste error back to AI | Human diagnoses, AI fixes | Agents self-diagnose within bounds; humans handle architecture |
| Appropriate scope | Prototypes, hackathons | Features in established codebases | Production, team-scale systems |
| Risk | High (acceptable for throwaway) | Moderate | Low (systematic verification) |

## 10. Essential skills in the AI era

1. **Know what to build and why** — does the requirement serve a real user problem?
2. **From implementer to orchestrator** — direct agents, evaluate output, give strategic direction, break work down, decide which parts need human judgment.
3. **Judge AI output** — code review for correctness, flexibility, maintainability; alternative designs; failure under extreme traffic; spot edge cases, permission leaks, bottlenecks, vulnerabilities, technical debt.
4. **Production engineering** — reliability, security, stability, incidents, long-term maintenance at scale.
5. **Stakeholder skills are core engineering skills** — talk to users/clients/business owners; the engineer who understands users and can translate that into precise agent instructions is far more valuable.

### Staying competitive

- Mediocre prototypes are easy now — **mediocre is no longer good enough**.
- **GitHub as the new resume**: a project with 3,000 stars used by hundreds can bypass entry-level experience requirements.
- Improve communication/presentation; develop taste and judgment.
- **Use AI with a learning mindset**: interrogate answers; build things from scratch to learn fundamentals — "You'll write worse code, but you'll understand every line. That knowledge compounds."
